# 赛博魔法 · 手势骨骼监测

用摄像头实时识别手部，在网页**右上角的小窗**中显示 21 个关节点、当前手势、
左右手、置信度、推理帧率和五根手指的伸展状态。

网页版不显示摄像头画面，也**不包含画笔、颜色、粗细、撤销、保存或鼠标绘制功能**。大屏还会开启赛博朋克城市背景、跟随玩家的青蓝色虚拟手，以及捏合聚能与蓝色能量球发射技能。
摄像头帧只在当前浏览器内存中交给 MediaPipe 处理，不会上传。

---

## 1. 运行

```powershell
# 在项目根目录
run_web.bat
```

或手动：

```powershell
.venv\Scripts\python.exe web_server.py
```

脚本会启动一个只监听 `127.0.0.1` 的静态服务器（默认 `http://127.0.0.1:8765/`），
并自动打开默认浏览器。端口被占用会自动往后找。

> **不要直接双击 `web/index.html`。** 浏览器只在 `https` 或 `localhost/127.0.0.1`
> 下允许使用摄像头。

### 环境要求

- Chrome / Edge（推荐最新版），需要 WebGL、WebAssembly SIMD
- 一个摄像头
- 不需要联网：MediaPipe 运行时、模型、页面全部内置在 `web/` 里

## 2. 状态窗说明

| 区域 | 含义 |
| --- | --- |
| 青色骨架 | 实时手部 21 点连线 |
| 高亮指尖 | 拇指、食指、中指、无名指、小指指尖 |
| 当前手势 | 捏合、食指指向、双指、张开手掌、握拳等 |
| 置信度 | MediaPipe 对当前手部检测的置信度 |
| LEFT / RIGHT | 检测到的左右手 |
| 底部五个圆点 | 对应手指当前是否伸展 |
| `GPU` / `CPU` | 当前使用的推理后端 |
| `FPS` | 实际检测频率 |

骨架会按手部包围盒等比缩放到小窗中央，不依赖摄像头画面的显示比例，
因此手掌远近变化时仍能保持完整可见。

### 识别到的手势

- 捏合：拇指尖与食指尖闭合
- 食指指向：仅食指伸展
- 双指手势：食指与中指伸展
- 三指手势：食指、中指、无名指伸展
- 张开手掌：五根手指全部伸展
- 握拳：五根手指全部收拢
- 其他变化姿态：显示为「手势变化中」

## 3. 大屏赛博朋克场景与技能

该技能只在 `min-width: 960px` 且 `min-height: 600px` 时启用；小屏不显示能量层，
也不会触发能量球。大屏启动摄像头后会使用双手机制，可同时识别两只手。背景为程序化绘制的赛博朋克城市，包含霓虹天际线、全息广告、雾层、雨丝和高架道路。主画面会显示一只由玩家 21 点骨架驱动的能量手；位置、朝向、手掌大小和手指弯曲都实时同步，并在两次模型检测之间按帧插值，保证快速移动时仍然顺滑。

| 操作 | 效果 |
| --- | --- |
| 玩家移动手 | 大屏能量手同步移动并保持手指姿势 |
| 拇指 + 食指捏合 | 只有捏合时出现蓝色能量球 |
| 保持捏合约 0.35 秒 | 能量球逐渐变大、旋转并出现电弧 |
| 松开捏合 | 能量球消失 |
| 手快速向前推 | 手掌放大或深度快速变化时，能量球向前发射 |
| 手快速向上/侧向挥动 | 能量球沿屏幕方向飞出 |

能量球由 canvas 程序化绘制：白色高亮核心、青蓝渐层、旋转能量环和内部电弧。发射后沿贝塞尔弧线飞向城市，命中时触发扩散冲击波、青蓝爆炸火球、上升能量柱、电弧和 76 个飞散粒子。技能有 0.85 秒冷却，避免连续误触。

## 6. 实现要点

- **21 点骨架**：全部关键点做 EMA 平滑，减少手抖造成的骨架跳动。
- **捏合识别**：拇指尖到食指尖的距离 ÷ 手掌尺度，使用双阈值滞回和连续帧确认。
- **手势分类**：根据五根手指的伸展状态组合，优先级为「捏合 → 单指 → 双指 →
  三指 → 张开手掌 → 握拳 → 其他」。
- **等比适配**：计算手部包围盒并等比缩放到小窗，避免不同手型和远近导致骨架被裁切。
- **隐私**：摄像头 `<video>` 只有 1px 且透明，只用于解码；不会绘制摄像头画面。
- **性能**：只在检测到新视频帧时推理；状态窗 canvas 只在状态更新或窗口尺寸变化时重绘。

| `?demo=1` | 不打开摄像头，用捏合脚本手显示状态窗、大屏虚拟手、能量球与城市背景（截图 / 验证布局） |

## 9. 常见问题

**Q：状态窗一直显示「等待手部进入画面」？**
A：先确认页面底部没有摄像头错误，然后把整只手放进摄像头中心区域。距离太近或只露出
一部分手掌时，MediaPipe 可能无法返回完整的 21 点。

**Q：摄像头打不开？**
A：检查摄像头是否被会议 / 直播 / 相机软件占用，以及笔记本的摄像头隐私开关。
必须通过 `http://127.0.0.1` 或 `https` 打开页面。

**Q：左右手显示反了？**
A：按 `M` 切换镜像。MediaPipe 的左右手分类基于摄像头输入方向，镜像是显示习惯。

**Q：骨架跳动或手势名称来回切换？**
A：编辑 `web/js/config.js` 的 `GESTURE.smoothing` 和连续帧参数。调小平滑系数更稳，
增大连续帧确认会降低误判但响应稍慢。

**Q：捏合太灵敏 / 捏不上？**
A：调整 `GESTURE.pinchStartRatio`：调小更难触发（如 `0.25`），调大更容易（如 `0.35`）。

**Q：端口 8765 被占用？**
A：`web_server.py` 会自动往后找可用端口，终端里会打印实际地址。
